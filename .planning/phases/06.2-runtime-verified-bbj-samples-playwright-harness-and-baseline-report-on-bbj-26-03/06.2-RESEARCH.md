## Summary

Every step of the harness was proven once by hand:

1. Registration from plain Java through `BBjAdminAPI.jar` works in about 2 s per call and uses **no BBj license**.
2. A registered program opens at `http://localhost:8888/webapp/<name>` and Playwright sees DWC's web components through open shadow DOM.
3. With console access explicitly **allowed** on the app, an untrapped error lands in DWC's WebCUI console with error number, message, line number and statement, and `PRINT` output is visible there. Playwright can read that console text from the xterm.js buffer.
4. Closing the browser does **not** end the BBj session. Sessions must be terminated through the Admin API after every test, because the machine has only **3 BBJ licenses**.
5. The local compiler finds no syntax errors in the 63 files. Its type checker (`-t`) finds one real bug class (void assigned to a declared control) among several hundred `<undeclared>` follow-up messages.

## 1. Registration: Admin API from Java, not from BBj

Verified with `javap` against `C:\bbx\.lib\BBjAdminAPI.jar` (the hosted BBj docs have no `BBjAdminFactory` page):

- `BBjAdminFactory.getBBjAdmin(String user, String password)` returns `BBjAdminBase`
- `BBjAdminBase`: `getRemoteConfiguration()`, `getBBjProcesses()`, `getLicenseFeatureInfo(String)`, `getAllLicenseFeatureInfo()`, `release()`
- `BBjAdminAppDeploymentConfiguration`: `getApplications()`, `getApplication(String)`, `createApplication()`, `removeApplication(String)`
- `BBjAdminAppDeploymentApplication`: `setString`, `setBoolean`, `getString`, `commit()`, `getDwcUrl(boolean)`; constants `NAME`, `PROGRAM`, `WORKING_DIRECTORY` (value `"DIRECTORY"`), `DWC_ENABLED`, `BUI_ENABLED`, `DISALLOW_CONSOLE`, `DISALLOW_CONSOLE_USE_DEFAULT`, `CONFIG_FILE`, `ERR_ACTION`, `ERR_ACTION_MSG`, `END_ACTION`
- `BBjAdminBBjProcess`: `getString(PROCESS_ID | PROGRAM_NAME | CONNECTION_TIME | NOT_RESPONDING)`, `terminate()`

Run it as `java -cp "C:/bbx/.lib/*" Tool.java ...`. `BBjAdminAPI.jar` alone fails with `NoClassDefFoundError: com/google/common/cache/CacheLoader`, so the whole `.lib` folder goes on the classpath.

**Why not a BBj program via `bbj.exe`:** it works (first run 1.6 s), but every run takes one of the 3 BBJ licenses. When licenses ran short, each run hung until the 90 s timeout even after writing its result, and one run failed with "problem starting BBj process". The Java route avoids both.

**Registration does not check the program path.** A wrong path registered fine and failed only at launch with `!ERROR=12 (Missing file ...)`. The tool must check that the file exists before registering.

Spike tool: `spike/AdminProbe.java` (modes `register`, `unregister <prefix>`, `list`, `kill <path marker>`, `killids <ids>`).

## 2. What DWC looks like to Playwright (observed)

| State | DOM signal |
|-------|-----------|
| App started | `dwc-window-content` exists; `document.title` equals the window title |
| Message box | `dwc-dialog` with title, message and button (DWC2 "Say Hello" showed "Hello World" / "Hello" / "OK") |
| Startup failure, console disallowed | `dwc-dialog` titled `Error` with `!ERROR=12 (Missing file ...)` |
| Runtime error, console disallowed | `dwc-dialog` titled `Error` with `!ERROR=252 (No match for method ...)`; no line number |
| Program reaches `END`, console disallowed | `dwc-dialog` "Thin Client Console Error: Program attempted to break to console, which is not allowed by the server" |
| Console allowed (error, `END`, `STOP`) | `dwc-frame.dwc-console-frame` containing `dwc-window-center.dwc-console__xterm` (xterm.js on `<canvas>`) |
| License exhausted | `dwc-dialog` "License Error ... [E3008] License BBJ out of licenses" |

**Console text:** `document.querySelector('.dwc-console__xterm').xterm` is the xterm.js `Terminal` (also at `.widgetManager.terminal`). `term.buffer.active.getLine(i).translateToString(true)` gives the lines. Observed output for an error:

```text
BBj WebCUI Console
Server BBj Version: REV 26.03
...
!ERROR=252  (No match for method jdk.proxy2.$Proxy171.noSuchMethod())
[4] st!.noSuchMethod()

READY
```

For `PRINT` programs the printed lines appear before `READY`. This is an undocumented internal: if a later DWC renames it, fall back to "console frame present = failure" plus a screenshot. Per the WebCUI page, the console terminal is free for debugging; a WEBCUI license is only checked out for `INPUT`, `READ` and similar verbs.

**Decision for the harness:** register every app with `DISALLOW_CONSOLE_USE_DEFAULT=false` and `DISALLOW_CONSOLE=false`. That gives error line numbers and makes the six print-style programs testable. A console frame in a window program means it crashed or ended early.

**Page errors are a real signal.** The minimal spike program logged no page errors. `DWC2.bbj` logged `pageerror: e.componentOnReady is not a function`. DWC's own console messages are four `console.log` lines ("Launching/Starting/Initializing/Running BASIS Dynamic Web Client") to ignore.

**`Debug.log` stayed empty** for every spike error. Keep a delta check (cheap), but don't rely on it.

## 3. Sessions and licenses (observed)

- With 3 BBJ licenses, the run is serial (`workers: 1`), and each test ends by terminating its sessions.
- After a probe, the session was still listed (crashed ones with `notResponding` counting up). Four sessions from the earlier `bbj.exe` attempts sat at `prog=<initializing>` and held licenses until terminated by ID.
- Cleanup rule: before a test, record the process IDs; after it, terminate every new process whose program path is under `docs/examples` or is `<initializing>`. Also run one sweep at the start and end of the run.
- Every test should also check BBJ licenses in use before starting and wait or fail clearly instead of showing a license-error dialog.

## 4. Compile pass (observed, all 63 files)

- `bbjcpl -N -X <file>` (syntax only): **no output for all 63 files**.
- `bbjcpl -t -N -X -W -cC:/bbx/cfg/config.bbx <file>` (run inside the file's folder): 37 files with type-check errors, about 470 messages. Almost all are follow-ups of undeclared variables (`String '+' expects type BBjString but got <undeclared>`, `Cannot assign <undeclared> to BBjString`, `No match for method ...(<undeclared>)`). These run fine; they are review material ("declare your variables"), not failures.
- **Real finding:** `Autocast will always fail on assignment from void to BBjEditBox` in `dwc/05_CssLayouts/Exercise-ConvertToCssFlexbox.bbj` lines 47 to 49 and `Exercise-ConvertToCssFlexboxComplete.bbj` lines 36 to 38: `myName! = window!.addEditBox("Joe Blow").setAttribute("label", "Name:")` stores the void result of `setAttribute`.
- Report filter: keep `Autocast will always fail ... from void`, and `No match for method` where every argument type is known. List the `<undeclared>` follow-ups only as a count per file.
- `bbjcpl` exits 0 even on errors (per the curated BBj skill); parse the output. The first line number is ten times the source line; the source line is in parentheses.
- Raw output: `spike/compile-all-raw.txt`.

## 7. Harness architecture (recommended)

```text
tools/sample-test/
  .env                      Eric's credentials (ignored)
  package.json              @playwright/test 1.64.0 exact, own lockfile
  playwright.config.js      workers 1, Chromium, baseURL http://localhost:8888, HTML report
  manifest.json             one entry per .bbj (path, kind, entry, deps, page, issues, scenario)
  admin/BBjAdminTool.java   register / unregister / sessions / kill / licenses (from spike/AdminProbe.java)
  lib/admin.js              spawn java with an args array (no shell), parse output
  lib/dwc.js                wait for start, read console buffer, collect page errors and failed requests
  compile.mjs               bbjcpl syntax and type-check pass -> results/compile.json
  global-setup.js           compile, sweep sessions, register all apps -> results/urls.json
  global-teardown.js        sweep sessions, unregister courses-*
  tests/coverage.spec.js    every .bbj under docs/examples has a manifest entry, and every entry exists
  tests/smoke.spec.js       one test per runnable entry, generated from the manifest
  tests/behaviour/*.spec.js behaviour from the page text, issues #3 to #7 explicitly
  report.mjs                results -> tools/data/sample-test-report.md
```

Pitfalls seen in the spike that the code must avoid:
- Git Bash rewrites arguments starting with `/` into Windows paths (MSYS path conversion), and shell quoting broke a backslash path twice. Spawn processes from Node with an argument array, never through a shell string.
- Never print the `.env` values; pass the file path to the Java tool, which reads it.
- App names: lowercase `courses-<book>-<slug>` with only `[a-z0-9-]`.
- The console header shows the BBj license serial number. Screenshots, DOM dumps and raw console text stay in the ignored `tools/sample-test/results/`; the committed report quotes console text only from the first `!ERROR` or printed line onward.
- The spike's `probe.mjs` and `xterm-probe.mjs` were run from `tools/sample-test/` (they import `@playwright/test` from its `node_modules`).

Timing: start to first window took about 3 to 4 s per program. With cleanup, about 10 to 15 s per test, so a serial run over about 60 programs takes roughly 10 to 15 minutes.

## Validation Architecture

The baseline run is expected to find broken samples, so a red sample is data, not a harness failure. The harness is "green" when it did its job: coverage complete, controls classified correctly, a result row for every manifest entry.

**Three layers:**

1. **Unit tests, no BBj needed** (`node --test tools/sample-test/lib/`, a few seconds): manifest validation, `bbjcpl` output parser (line number in parentheses, `<undeclared>` filter), console text parser (finds `!ERROR=n`, message, `[line] statement`, printed lines; strips the header with the serial number), app-name builder (`[a-z0-9-]` only), report generator from fixture results.
2. **Harness self-test against controls** (`npx playwright test --project=selftest`, about 1 minute, needs BBjServices): fixtures in `tools/sample-test/fixtures/` (outside `docs/examples/`, so the coverage test ignores them):
   - `known-good.bbj`: a window with a static text and a button that opens a message box. It must be classified `pass`.
   - `known-broken.bbj`: a window, then a call to a method that doesn't exist. It must be classified `fail` with `!ERROR=252` and line number 4 in the result.
   - `known-print.bbj`: prints two lines and ends. It must be classified `pass` with both lines captured.
   - `known-missing-css.bbj`: injects a link to a CSS file that doesn't exist. It must be classified `fail` with an HTTP 404 in the network findings.

   The self-test asserts the harness's classification, not the program's behaviour, and checks that no fixture session is left running afterwards.
3. **Full baseline** (`npm run baseline` in `tools/sample-test/`, about 15 minutes, needs BBjServices and network): compile pass, sweep sessions, register all, coverage test, self-test, smoke and behaviour tests for every sample (Playwright exit code ignored), report, unregister. `run-baseline.mjs` exits non-zero only if the coverage test or the self-test fails, a manifest entry has no result row, or apps or sessions are left behind.

**Requirement to check mapping:**

| Requirement | Automated check |
|-------------|-----------------|
| SAMP-01 | `tests/coverage.spec.js` (globs `docs/examples/**/*.bbj` against `manifest.json` both ways) |
| SAMP-02 | `results/compile.json` has 63 entries; unit test for the parser |
| SAMP-03 | self-test registers the fixtures and finds their URLs; after teardown the Java tool lists no `courses-` apps and no sessions under `docs/examples` or `fixtures` |
| SAMP-04 | self-test classifications (pass, fail with line, print lines, 404) |
| SAMP-05 | every manifest entry of kind `window` has a smoke result; entries with issue numbers #3 to #7 have a named behaviour test (`grep` the test titles) |
| SAMP-06 | `tools/data/sample-test-report.md` exists, has one row per manifest entry, contains the sections "Draft issues" and "Questions for Hyyan", and does not contain the license serial number; `git diff --stat docs/` is empty |
