## Issue #3 evidence (for Eric)

Issue #3: "Setting the css with @app-style on the window doesn't appear to have an impact in current BBj". The test `[dwc/01_GUI2BUI2DWC/DWC_ExternalCSS/Sample.bbj] issue #3: ...` is red, and the result file says why:

- The program runs to the end: line 16 reads `Sample.css` through `resolvePath` without error, so the missing-file outcome did not occur.
- `addPanelStyle("mypanel")` (line 20) works: exactly one element has the class `mypanel`, and it is the `dwc-window-content` panel.
- The CSS from line 18 never arrives: 0 of 9 `<style>` elements (document and shadow roots) contain `.mypanel`. The computed style of the panel is `display: block`, `grid-template-columns: none`, `gap: normal`, `padding: 0px`; the file says `inline-grid`, `1fr 1fr`, `5px`, `15px`. The screenshot shows the labels, edit boxes and button in one row with no gap and no padding.
- Cause as DWC states it: the browser console logs the error "Starting from BBj v23.00, the attributes directives are no longer available. Instead, their equivalent can now be found in BBjWebManager." (the full message ends with a link to the migration guide). `@app-style` is such a directive.
- The mechanism the message names works in this book: `DWCThemer.bbj`, `CSSCustomProperties.bbj`, `SetStyle.bbj` and `Exercise-ThemingSupportComplete.bbj` all inject CSS with `BBjAPI().getWebManager().injectStyle(...)` and their tests are green (the injected `:root { ... }` rule is found in a `<style>` element). Replacing line 18 with `injectStyle(css!)` is therefore the likely fix. It was not tried: samples are never changed.

## Issue #4 evidence (for Eric to take to Hyyan)

Issue #4: "Is there a better way in modern DWC / BBj to do this?" (`DWC2.bbj` line 35). The test `[dwc/01_GUI2BUI2DWC/DWC2.bbj] issue #4: ...` is green: the icon works on 26.03. The result file records the markup:

- Program: `btn! = wnd!.addButton("<html>Say Hello " + btnIcon$ + "</html>")` with `btnIcon$ = "<dwc-icon name='speakerphone'></dwc-icon>"`.
- In the DOM the button content is `Say Hello <dwc-icon name="speakerphone" expanse="xs" pool="tabler" theme="default" class="hydrated"></dwc-icon>`: a `dwc-icon` that is a light-DOM child of the `dwc-button` host. DWC adds `pool="tabler"`, `expanse="xs"` and `theme="default"` itself. The icon is 26 x 26 px and its shadow root draws an svg with child elements.
- `iconReport`: total 5, rendered 1, missing 0, hidden 4 (DWC's own, never visible, so not judged).
- From a probe run (not stored): the button's accessible name is "Say Hello speakerphone" (the icon contributes its name), and the `dwc-button` shadow DOM has `prefix`, `suffix`, `left-edge`, `right-edge` and `badge` slots. Whether BBj exposes one of those slots as an icon API, instead of an HTML string in the title, is the question for Hyyan. The same pattern is used in `Exercise-ThemingSupportComplete.bbj` (`<html><dwc-icon name='sun'></dwc-icon> Light`); in a probe its button showed up with the accessible name "sun Light", and the toggle test is green, but no test asserts that icon.
