# Phase 06.2: Runtime-verified BBj Samples - Context

**Gathered:** 2026-10-08 (chat with Eric Handtke, no separate discuss session)
**Status:** Ready for planning

<domain>
## Phase Boundary

Stephan Wald reviewed the course samples for AI training and found many of them broken on BBj 26 (GitHub issues #3 to #7). He asked Eric to test every program in the corpus and fix it to modern BBj DWC practice, checking with Hyyan where unsure.

This phase delivers the testing half: a local harness that compiles every `.bbj` under `docs/examples/`, registers every runnable program as a DWC app, runs it in Chromium with Playwright, and writes one baseline report. Fixing the samples is the next phase, after Eric has read the report.

</domain>

<decisions>
## Implementation Decisions

### Locked (user, 2026-10-08)
- **D-01:** DWC only. No BUI runs, no desktop GUI runs. The GUI comparison samples (`GUISample`, `ArcSample`, `GUIGridSample`) run in DWC like every other program. The BUI-to-DWC relaunch block in most samples is assessed by reading the code, not by running BUI.
- **D-02:** Chromium only for the baseline. Firefox and WebKit can follow later.
- **D-03:** No sample changes in this phase. The harness records what is broken; fixes wait until Eric has read the report and decided.
- **D-04:** Nothing is posted to GitHub (no issues, no comments, no push). Findings, draft issue texts and questions for Hyyan go into the report and to Eric.
- **D-05:** Admin credentials live in `tools/sample-test/.env` (keys `BBJ_ADMIN_USER`, `BBJ_ADMIN_PASSWORD`), created by Eric and ignored by the root `.gitignore` rule `.env`. The harness folder is `tools/sample-test/` because that is where the file was created. Credentials never appear in logs, reports or commits.
- **D-06:** Registering about 60 `courses-*` apps on the local BBjServices is approved. One script removes all of them again.
- **D-07:** Work happens on the local branch `sample-tests`. Commits are fine, pushing is not.
- **D-08:** Samples are AI training data. The harness never adds IDs, `data-testid` attributes or other test hooks to them; tests locate controls by role and visible text.
- **D-09:** The harness runs locally only. GitHub CI has no BBj.

### Claude's Discretion
- Test file layout, manifest format, report layout
- How deep each behaviour test goes; the course page text is the spec for what a sample should do
- Whether screenshot baselines are stored now or after Eric's first look

### Deferred Ideas (OUT OF SCOPE)
- Fixing any sample, page or ZIP (next phase)
- Review of the 143 inline BBj fences in 45 pages that are not files in `docs/examples/`
- Firefox and WebKit runs
- Wiring the harness into CLAUDE.md "Before committing" (do it when the fix phase starts, so a red baseline does not block unrelated commits)

</decisions>
