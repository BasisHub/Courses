## Issue #5 evidence (for Eric)

Issue #5: "is --dwc-space overcome?" (`LabelAttributes.bbj` line 34 reads `var(--dwc-space)`; it read `var(--bbj-space)` when the issue was filed, commit 777682c replaced it). The test `[dwc/04_ExtendedAttributes/LabelAttributes.bbj] issue #5: --dwc-space resolves on BBj 26.03` is green. The result file records:

- `--dwc-space = 0.5rem` on `<html>` and on the window panel (`dwc-window-content`). The vendored `docs/static/css/dwc-ui.css` declares `--dwc-space: var(--dwc-space-s)`, and the live value `0.5rem` is `--dwc-space-s`, so the token behaves as the snapshot says.
- `--bbj-space = (empty)`: the old name is gone.
- The scale resolves too: 3xs 0.0625rem, 2xs 0.125rem, xs 0.25rem, s 0.5rem, m 1rem, l 1.25rem, xl 1.5rem, 2xl 1.75rem, 3xl 2rem.
- The panel itself shows `padding-top: 0px` and `row-gap: normal`, although lines 34 to 40 set padding and gap to `var(--dwc-space)` through `setPanelStyle("@element", ...)`. The cause is not the token. DWC logs "Starting from BBj v24.00, the style directives are no longer available" for this sample, and the panel style from the JSON never reaches the page (the screenshots show the controls in a flow layout without padding). That is issue #7 (plan 13 has the issue #7 test for this file).
- Answer for Eric: `--dwc-space` is valid and current on 26.03. Nothing replaces it. The sample's problem is the style directive, not the variable.
- One observation from the vendored file, not tested live: `.bbj-icon{padding:var(--bbj-space-xs)}` in `dwc-ui.css` still refers to a `--bbj-space-xs` token that file does not declare.
