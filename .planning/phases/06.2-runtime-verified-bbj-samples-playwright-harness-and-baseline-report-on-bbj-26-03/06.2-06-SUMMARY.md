## The injectLinkUrl answer (needed by the report)

Source: https://documentation.basis.cloud/BASISHelp/WebHelp/bui/BBjBuiManager/BBjBuiManager_injectLinkUrl.htm (BBj 22.03 and higher)

1. **First argument:** a URL, "injected into this web page as a link element". Not a whole `<link>` tag.
2. **Overloads:** `injectLinkUrl(url)`, `(url, boolean top)`, `(url, top, String attributes)`, `(url, top, HashMap attributes)`. Attributes as a string use the form `attr=value,attr=value`.
3. **rel:** both documentation examples pass `rel=stylesheet` (or `rel="stylesheet"`) to load a stylesheet and `rel="preconnect"` for preconnects. A link element without `rel` is not fetched by the browser.

**Report finding:** `docs/examples/dwc/05_CssLayouts/DWCFlexbox.bbj` (lines 469 to 471) and `DWCFlexbox.BBj24.bbj` (lines 396 to 398) pass whole tags such as `"<link rel='preconnect' href='https://fonts.googleapis.com'>"` as the URL argument. By the documentation that injects a link whose href is the tag text, so the intended preconnects and the Google Fonts stylesheet are not loaded as written. The plan 16 report should list this, together with the Google Fonts use itself.

## Deviations from Plan

### Fixed during the check

**1. known-missing-css.bbj could not fail**
- **Found during:** Task 1, injectLinkUrl lookup
- **Issue:** `web!.injectLinkUrl("/courses-fixture-does-not-exist.css", 1)` injects a link without `rel`; the browser never requests it, so no 404 would ever be observed and the control would wrongly pass.
- **Fix:** line 3 is now `web!.injectLinkUrl("/courses-fixture-does-not-exist.css", 1, "rel=stylesheet")`, the documented three-argument form. The fixed text passed a new `bbj_check_syntax` call and the local compiler.
- **Files modified:** tools/sample-test/fixtures/known-missing-css.bbj
- **Commit:** see `docs(06.2-06): record BBj check of harness control programs`

### Result value for known-broken.bbj

The plan foresaw `expected` for a finding on line 4 only. The hosted check returns no finding at all, because a call to a missing method is a runtime error (`!ERROR=252` at run time, observed in the spike), not a parse error. The row records `pass`; the deliberate line 4 is unchanged.
