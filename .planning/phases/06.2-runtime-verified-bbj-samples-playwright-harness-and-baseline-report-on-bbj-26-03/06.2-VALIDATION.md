> Per-phase validation contract for feedback sampling during execution.

A red sample in the baseline is a finding, not a failed check. Checks here prove the harness works: coverage, correct classification of control programs, a result row per sample, nothing left behind.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Node 24 `node:test` (unit, coverage), `@playwright/test` 1.64.0 (self-test, smoke, behaviour) |
| **Config file** | `tools/sample-test/playwright.config.js` (plan 05 creates it) |
| **Quick run command** | `cd tools/sample-test && node --test lib/*.test.js tests/*.test.js && npx playwright test --project=selftest` |
| **Full suite command** | `cd tools/sample-test && npm run baseline` |
| **Estimated runtime** | quick: about 2 minutes (unit seconds, self-test needs BBjServices); full: about 30 to 45 minutes |

`node --test lib/` (directory argument) does not work on Node 24; pass the globs, Node expands them itself (also under cmd.exe).

---

## Sampling Rate

- **After every task commit:** `node --test lib/*.test.js tests/*.test.js` (seconds); from plan 05 on also the self-test
- **After every plan wave:** quick run command, then `node cleanup.mjs` (prints CLEAN)
- **Before `/gsd:verify-work`:** full suite completes, exit code 0 (plan 14)
- **Max feedback latency:** about 2 minutes for the quick run
