## Deadline each test body gets

The `bbj` fixture has its own 90 s timeout, so license wait, session snapshot and teardown do not use the body's budget. After a deadline, `timeoutEvidence` takes at most 5 s for the screenshot and 5 s for the console text, so the test ends before its own timeout with 5 s to spare.

## behaviourTest usage example (plans 10 to 15 copy this)

```js
import { expect } from '../../lib/fixtures.js';
import { behaviourTest, BlockedError } from '../../lib/behaviour.js';

behaviourTest(
  'dwc/01_GUI2BUI2DWC/DWC2.bbj',          // manifest id, or 'fixture/<file>' for a control
  'speaker icon renders',                  // title: [<id>] issue #4: speaker icon renders
  { issue: 4 },                            // opts: issue, startDialog, expectFailure, deadlineMs
  async ({ page, app, note }) => {
    const button = page.getByRole('button', { name: 'Say Hello' });   // role and visible text, no hooks
    await expect(button).toBeVisible();
    note('button found by role and visible text');                    // evidence
    if ((await page.locator('dwc-icon').count()) === 0) throw new BlockedError('no icon element on the page');
  },
);
```

Rules the wrapper enforces: the sample is opened first (a sample that does not start gives `blocked` with the first classify category, `license` when no license was free); a thrown error is a `fail` (category `assertion`), `BlockedError` is `blocked` (category `check`); a BBj `!ERROR` in the console after the body is a `fail` (category `bbj`); a hang is a `fail` (category `timeout`); the file goes to `results/behaviour/<app>--<title cut to 60>.json` (`selftest-behaviour` for fixture ids), the screenshot to `results/screenshots/<app>--<title cut to 40>.png`. Two tests on one sample need titles that differ within their first 40 characters. Behaviour plans must not change anything under `lib/`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug in the plan] A behaviour spec file is not the file Playwright reports for its tests**
- **Found during:** Task 1 (`--list` output)
- **Issue:** Playwright reports the call site of `test()`, which is `lib/behaviour.js` for every test made by the wrapper. The plan's check ("spec titles whose file starts with `behaviour/`") would have found no behaviour test at all.
- **Fix:** `behaviourTitles` reads the file from the file suite (the top-level suite) that the spec sits in. Proved with a temporary spec in `tests/behaviour/` against the real JSON, and with unit tests on the JSON shape.
- **Files:** `lib/behaviour-check.js`, `check-behaviour.mjs` | **Commit:** `5d7b625`

### Additions beyond the plan (Rule 2, all covered by tests)

**2. [Rule 2 - Missing critical functionality] The samples run is judged by its JSON report, not only ignored**
- **Issue:** the plan ignores the exit code of the sample tests. In a `--grep` run (where completeness is skipped) a failed global setup or a pattern that matches no test would then end with exit 0 and no result, and the baseline would call it clean.
- **Fix:** the runner passes `--reporter=list,json` and reads stats and errors: global errors, or no executed test, is a harness failure (`samplesRunFailures`). Red tests stay findings.
- **Files:** `lib/baseline.js`, `run-baseline.mjs` | **Commit:** `5d7b625`

**3. [Rule 2] The rules live in pure modules with unit tests.** `lib/baseline.js` (completeness, harness issues, summary, samples run) and `lib/behaviour-check.js` (titles, missing list, issue list), 16 tests. The full baseline takes an hour, so the rules must not be discovered by running it. Also `lib/behaviour.test.js` (18 tests) for the deadline race and the outcome rule.

**4. [Rule 2] Runner robustness.** `startedAt` is taken after the lock is held; a run that could not take the lock never writes `baseline.json` (another run may be writing results); an old `baseline.json` is deleted at the start so a run that dies half way cannot pass for the last one; `baseline.json` is written before the report step so the report shows this run's harness failures.

**5. [Rule 2] Richer evidence.** An assertion failure keeps the Locator, Expected and Received lines that Playwright prints below its first line, so a report row says what was looked for. `note(text)` is evidence: the only evidence of a pass, a suffix of a fail, the `last note` of a timeout. A BBj error also catches error dialogs, not only the console.

### Other differences

- **Unit-test child without the lock token.** The plan sets `COURSES_LOCK_TOKEN` for every child. The runner clears it for `node --test` (the unit tests use temporary lock files and must not see the real token); Playwright, the compile pass and cleanup get it.
- **Self-test results label.** A harness issue in a control program is labelled `[self-test control]`; the plan only names `<test or 'smoke'>`.
- **`resultsDir('baseline.json')`** works in this checkout (`lib/paths.js` creates only the parent folder for a path with a file extension), so plan 04's warning about it did not apply and the call is used as written.
- **Commit trailer.** The plan asks for `Claude Opus 5.5`; the orchestrator allows the model that did the work. Every commit carries the single line `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- **Full smoke pass in this plan.** The plan runs subsets live and leaves the full baseline to plan 16. The orchestrator asked for smoke timings and counts, so the 59-sample smoke stage was run once (see above). The behaviour part of the baseline does not exist yet.

## Issues Encountered

- **The 30-minute background limit killed the first full smoke pipeline.** The Bash tool stops a background command after 30 minutes even when a longer timeout is given. The pipeline (compile 3.5 min, unit tests, self-test 4 min, smoke 21 min) reached sample 57 of 59 and was stopped, so there was no teardown, no completeness check and no report. Recovery: no harness process survived; `node cleanup.mjs` took over the stale lock (dead pid), removed the 63 registered apps and printed `CLEAN` (0 sessions were left); the last two samples were run with a direct Playwright call and `CLEAN` again. **For plan 16 (60 to 90 minutes):** start the baseline detached, not as a plain background command. A probe confirmed that a child started with PowerShell `Start-Process` survives the call that launched it (it wrote its file 12 s after the launching call had returned); the exact redirect form for `results/baseline.log` was not tried. Poll the log and `results/baseline.json`, and run `node cleanup.mjs` if a run is ever stopped. The stale-lock takeover and the cleanup after a hard kill both worked as designed.
- **Observation, not a fix.** `SysPrint.bbj` waits out the full 30 s start timeout in smoke (33.8 s), so a baseline cannot get below about 21 min for the smoke stage even if every other sample is fast.
- **Mixed clock.** The session clock jumped by about an hour during the interrupted run; all durations above come from result timestamps and `baseline.json`, not from wall-clock differences across the gap.
