## Needs your attention: runtime-only questions for the human run

A parse check cannot answer these. They stay open until someone runs the samples (Assumptions A1, A3, A5, A6, A8). What the docs said about each:

- **A1, `Exercise-EmbedComponentComplete.bbj`: the `sl-rating` value type.** `BBjWebEventOptions::addItem` returns the JS expression result in `getEventMap`. The draft wraps it in `String(...)`, and `str()` converts any object to its string form (`str_function_bbj.htm`). Needs a DWC run to confirm `sl-change` fires and the value shows.
- **A3: `BBjFileSystem::resolvePath` base directory.** It resolves against configured prefixes (`BBjFileSystem_resolvePath.htm`). Whether `"./file.css"` resolves next to the program depends on the runtime working directory and PREFIX. Needs a run.
- **A5, `TicTacToeComputer.bbj`: MinMax recursion.** The METHOD page says a method defines a variable scope and local variables are only visible within that method. It does not say explicitly that each recursive call gets its own copies. Needs a run.
- **A6, `LoginDialog.bbj` and `ResponsiveLoginDialog.bbj`: return from a callback label inside a method.** The BASIS `dialog.src` sample (on the `BBjSysGuiEvent::getControl` page) uses `process_events` inside a method with a callback label (`doReturn:`) that ends in `methodRet`, which matches the cancel and success path. A plain `return` from the `login:` label that resumes `process_events` for the wrong-pair path is not shown in the docs. Needs a run.
- **A8, `Exercise-ButtonTransitionComplete.css`: hover scale on a DWC button.** Whether `transform: scale()` on the grow-button class lands on the visible DWC button (fallback `::part(control)`) needs a browser run.
