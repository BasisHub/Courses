## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR author code to Actions runner | PR content (including from forks) runs in test-build and reviewdog jobs |
| Actions runner to GitHub Pages | deploy job holds `pages: write` and an OIDC token |
| Third-party action code to runner | vale-action and reviewdog run with the job token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Tampering | errata-ai/vale-action | mitigate | Pinned to full commit SHA 518a9136acc6e6668ce7c00d367051e0941e87ff; `version: 3.24.0`; `sync: "false"` so styles come from the repo, not a download |
| T-02-12 | Elevation of privilege | GITHUB_TOKEN scopes | mitigate | Top-level `contents: read` everywhere; `pull-requests: write` only in reviewdog; `pages: write` + `id-token: write` only on the deploy job; `persist-credentials: false` on the test-build and deploy checkouts |
| T-02-13 | Elevation of privilege | PR-triggered workflows | mitigate | Only `pull_request` (never `pull_request_target`), so fork PRs get a read-only token and no secrets; deploy has no PR trigger |
| T-02-14 | Spoofing | Required status checks | mitigate | Contexts pinned to GitHub Actions app via `integration_id` in ruleset-main.json (confirmed from real check runs in 02-06) |
| T-02-15 | Denial of service | Required checks never reporting | mitigate | No `paths`/`paths-ignore` filters on required workflows; `[ci]` check enforces it |
