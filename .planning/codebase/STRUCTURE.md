## Directory Purposes

**`.planning/`:**
- Purpose: Track scope, decisions, phases, and planning artifacts
- Contains: PROJECT.md (scope), ROADMAP.md (phases), STATE.md (current status), migration-seed.md (spec), phases/ (per-phase plans), research/ (investigation), codebase/ (THIS map)
- Never committed to site build; strictly for internal planning

**`docs/`:**
- Purpose: Docusaurus site root; all content and configuration that becomes the published site
- Key files: docusaurus.config.js (Docusaurus config), package.json (dependencies), sidebars.js (navigation)
- Node version: 24 (specified in .nvmrc)

**`docs/docs/`:**
- Purpose: Content source (Markdown and MDX files for all books and pages)
- Layout: Two subdirectories (intro-bbj, dwc) + one unlisted fixture (authoring)
- Naming: Sections use `<N>-kebab-case-name/` (e.g., `01-getting-started/`); pages use `<NN>-name.mdx` (e.g., `02-loops-and-conditions.mdx`); exercises use `9N-exercise-name.mdx`

**`docs/src/`:**
- Purpose: Docusaurus theme customization, React components, styles, and configuration data
- Key subdirectories: components/ (YouTube, ExpandableCode, TableWrapper), css/ (SCSS), data/ (books.js registry), theme/ (MDXComponents, Prism config), pages/ (React-only pages like landing page)

**`docs/static/`:**
- Purpose: Static assets served directly (no processing)
- Contains: Vendored CSS (dwc-ui.css), brand images, client-side scripts (theme switcher, link decorator), downloadable zips

**`docs/examples/`:**
- Purpose: Source code samples for lessons (BBj and DWC)
- Layout: Per-book subdirectories (dwc/, intro-bbj/), then by topic (01_GUI2BUI2DWC/, etc.)
- Sync: Must be kept in sync with downloadable zips in `docs/static/files/` via `tools/sync-samples.py`

**`tools/`:**
- Purpose: Automation, validation, and verification scripts
- Key scripts: verify-phase*.sh (phase validation gates), check-*.py (specific area checks), moodle2docusaurus.py (throwaway converter), sync-samples.py (keeps examples in sync)
- Data artifacts: dwc-gap-audit.md, image maps, screenshot audit, bbj-token-verification.md

**`docs/build/`:**
- Purpose: Build output (static HTML, JS, CSS)
- Generated at: `npm run build` in docs/
- Published to: GitHub Pages (https://basishub.github.io/Courses/) on push to main
- Gitignored: Not committed to repo

## Naming Conventions

**Files:**
- Markdown/MDX: `<NN>-kebab-case-name.mdx` (two-digit prefix for ordering)
  - Regular pages: `01-`, `02-`, ...
  - Exercises: `90-`, `91-`, ... (reserved range for exercises within a section)
- Images: `kebab-case-no-spaces.png` or `.svg` (no timestamps, no spaces)
- Code samples: `PascalCase.bbj` or `.java` (matches style of examples/ subdirectories like `01_GUI2BUI2DWC/`)
- Directories: `<N>-kebab-case-name/` (two-digit position prefix, lowercase, hyphens for spacing)

**Markdown/MDX Front Matter:**

```yaml
---
title: "The human-readable title (shows in page and sidebar)"
description: "One-sentence overview for SEO and card descriptions"
sidebar_label: "Shorter label if title is too long"
sidebar_position: 1
---
```

**CSS Variables:**
- Token names: `--dwc-<category>-<property>` (all lowercase, hyphens)
  - Examples: `--dwc-color-primary-text`, `--dwc-surface-2`, `--dwc-code-keyword`, `--dwc-border-color`
- Location: `docs/static/css/dwc-ui.css` (vendored, do not edit)
- Reference in SCSS: `var(--dwc-color-primary-text)` (never hardcode colors)

**React Component Files:**
- Directory: PascalCase matching component name
  - Example: `docs/src/components/YouTube/`, `docs/src/components/DocsTools/ExpandableCode/`
- Files: `index.js` (component logic), `styles.css` (component-scoped styling)

**Book and Section IDs:**
- Must be kebab-case and permanent once assigned (they become URL slugs)
- Examples: `intro-bbj`, `dwc`, `getting-started`, `browser-developer-tools`

## Where to Add New Code

**New Chapter/Section in a Book:**
1. Create directory: `docs/docs/<book-id>/<N>-kebab-case-name/`
2. Create files:
   - `_category_.json` (metadata): 
     ```json
     {
       "label": "Human-readable section title",
       "position": <N>,
       "link": {"type": "doc", "id": "<book-id>/<section-id>/index"}
     }
     ```
   - `index.mdx` (section overview)
3. Add numbered pages: `01-page.mdx`, `02-page.mdx`, etc.
4. Add exercises: `90-exercise-name.mdx`, `91-exercise-name.mdx`
5. Add images: Create `img/` subdirectory in the section, use relative paths in markdown

**New Page/Lesson:**
1. Create file: `docs/docs/<book-id>/<section>/<NN>-kebab-case-name.mdx`
2. Front matter:
   ```yaml
   ---
   title: "Page Title"
   description: "Brief description"
   ---
   ```
3. Content: Start with ## (H2); use custom components (YouTube, ExpandableCode, etc.) as needed

**New Code Sample:**
1. Create file: `docs/examples/<book-id>/<TopicFolder>/FileName.bbj` (or .java, .css)
2. Verify syntax: `bbj_check_syntax path/to/file.bbj` (for BBj files)
3. Reference in a markdown file: Inline fence or download link to `static/files/<book-id>/<TopicFolder>.zip`
4. Keep in sync: Run `tools/sync-samples.py` to ensure the corresponding zip in `static/files/` matches

**New Custom Component:**
1. Create directory: `docs/src/components/<ComponentName>/`
2. Create files:
   - `index.js` (React component)
   - `styles.css` (component-scoped styles using `--dwc-*` tokens)
3. Import and register in `docs/src/theme/MDXComponents.js`:
   ```javascript
   import MyComponent from '@site/src/components/MyComponent';
   
   export default {
     ...MDXComponents,
     MyComponent,
   };
   ```
4. Use in any .mdx: `<MyComponent prop="value" />`

**New Utility Script:**
1. Create file: `tools/script-name.py` or `tools/script-name.sh`
2. Add docstring/comment explaining purpose and usage
3. For Python: Add to `requirements.txt` if new dependencies needed
4. For phase verification: Create `tools/verify-phase<N>.sh` with check harness

**Styling Changes:**
1. **Global styles:** Edit `docs/src/css/custom.scss` (for site-wide changes like font stack)
2. **Component-scoped:** Edit `docs/src/css/_<area>.scss` (for specific UI areas; all import into custom.scss)
3. **Single component:** Edit `docs/src/components/<ComponentName>/styles.css`
4. **Always use:** `var(--dwc-*)` CSS custom properties, never hardcoded colors

## Special Directories

**`docs/.docusaurus/`:**
- Purpose: Docusaurus build cache
- Generated: Automatically by `npm run build` or `npm start`
- Committed: No (gitignored)
- Safe to delete: Yes; will be regenerated on next build

**`docs/build/`:**
- Purpose: Static HTML output
- Generated: By `npm run build`
- Committed: No (gitignored)
- Contents: All HTML, JS, CSS, images needed to serve the site
- Published: Automatically to GitHub Pages on push to main

**`docs/node_modules/`:**
- Purpose: Installed npm packages
- Generated: By `npm install` or `npm ci`
- Committed: No (gitignored)
- To update: Edit package.json, run `npm install`, commit package-lock.json

**`.planning/`:**
- Purpose: Internal project planning (not published)
- Committed: Yes
- In site build: No (gitignored in Docusaurus build)

**`tools/data/`:**
- Purpose: Generated audit and mapping files from phase execution
- Examples: dwc-gap-audit.md (missing content audit), image maps, screenshot lists
- Committed: Yes (results of validation phases)
- Kept current: When phase verification runs, files may be updated with new findings

**`import/`:**
- Purpose: Local temporary workspace for Moodle backups and conversion artifacts
- Committed: No (gitignored)
- Lifecycle: Created during phase execution, deleted after artifacts (image maps, gap audit) are extracted to tools/data/
- Not persistent: Nothing in import/ persists in the repo after a phase is complete
