# Project Research Summary

**Project:** BASIS Courses
**Domain:** Multi-book, reading-only Docusaurus training site (webforJ look), with a one-time Moodle-to-Markdown conversion, a repo relocation and a legacy redirect build
**Researched:** 2026-10-03
**Confidence:** MEDIUM-HIGH

## Executive Summary

This is a static documentation site, not an LMS. The proven build is:
- one Docusaurus docs plugin instance
- one autogenerated sidebar per book
- structure taken from the paths (folders plus `_category_.json`)
- webforJ's SCSS and theme overrides copied as a set

The risk sits in three one-way data flows: the throwaway Moodle converter, the pure DWC-Course relocation, and the redirect-only build for old URLs.

`.planning/migration-seed.md` has the right intent but is wrong in about a dozen specifics, which the researchers checked against the real `.mbz` archives, the real DWC-Course checkout and the npm packages. Build on the corrected facts below, not on the seed text.

Recommended approach:
1. Scaffold the site and prove deployment on an empty site first. The `/Courses/` baseUrl breaks many assumptions in the copied webforJ files.
2. Build the shared components before any content lands: the exercise admonition, YouTube, ExpandableCode, TableWrapper and the Prism BBj extension.
3. Move the DWC book as a pure relocation.
4. Run the converter, commit its output and extract the exercises.
5. Run the DWC gap audit, then hand review and Vale.
6. Accept and go live.
7. Build the redirects last.

Key risks:
- **Content before components:** the build throws on unknown components or admonition types, so components must land before converted content.
- **Converter report:** an "all zeros" report can still hide broken links and images unless its counters and the acceptance grep cover the real Moodle token forms.
- **Vale:** Vale reports zero issues on `.mdx` files it never checked unless the glob is fixed.
- **Redirects:** the redirect build loses `#fragments` and returns 404s unless it forwards `location.hash` and ships a `404.html`.
- **2022-screenshot flag:** this cannot come from DWC filenames. It needs content-hash matching.

## Resolved Disagreement: Docusaurus Version Pin

STACK recommends exact `3.10.2`; PITFALLS recommends pinning what webforJ uses (`^3.9.1`).

**Decision:** pin all six `@docusaurus/*` packages to exactly `3.10.2` (no carets), commit `package-lock.json`, and use `npm ci` in CI.

- **Why this choice:** exact pins plus a lockfile solve the config-drift concern behind PITFALLS' advice. `^3.9.1` would float to 3.10.2 anyway.
- **Config:** the non-deprecated hook forms are the same on 3.9.2 and 3.10.
- **Fallback:** if a swizzle misbehaves on 3.10, use exact `3.9.2`, which DWC-Course already runs on React 19. Record the choice in `CLAUDE.md`.
- **Avoid:** never use `4.0.0-canary`, and never copy webforJ's React 18 or its other version numbers.

Other resolutions:
- **Node:** 24 on CI (Node 20 is EOL); `engines >=20` and `docs/.nvmrc` set to 24.
- **HTML parser:** BeautifulSoup with `html.parser` for Moodle HTML, because lxml restructures `<p>` inside `<code>`. Use lxml or ElementTree only for the backup XML.
- **Relocated top-level pages:** keep them `.md` in the pure relocation. Number them `00-overview`, `00-prerequisites`, `98-samples`, `99-resources`.
- **Prism BBj:** keep `'bbj'` in `additionalLanguages`, since the built-in grammar exists. Swizzle `prism-include-languages` and extend or overwrite `PrismObject.languages.bbj` after the standard loop, on the passed `PrismObject`, with standard token names only.

## Where Research Contradicts `.planning/migration-seed.md`

| Seed says | Research found | Consequence |
|---|---|---|
| Prism has no BBj grammar (6.4) | `prismjs@1.30.0` ships a thin `prism-bbj.js`; DWC-Course builds only because of it | Extend it rather than writing one; verify keywords via the BBj MCP |
| `<!-- TODO: screenshot outdated? -->` | HTML comments are invalid in MDX, and `.md` is MDX by default | Use `{/* TODO: screenshot outdated? */}`. Don't set `format: 'detect'`. Add a Vale `TokenIgnores` entry |
| `:::exercise` needs only `keywords` | No fallback for unknown admonition types | Swizzle `src/theme/Admonition/Types.js` and add `.alert--exercise` |
| Internal links are `view.php?id=N` | The real forms are `$@PAGEVIEWBYID*57@$`, `$@COURSEVIEWBYID*4@$#section-1` and `&forceview=1`. Course 4 section summaries use absolute `moodle.basis-europe.eu/pluginfile.php` URLs (component `course`, filearea `section`) | Resolve files by the tuple (contextid, component, filearea, itemid, filename). Acceptance grep: `PLUGINFILE\|pluginfile\.php\|\$@[A-Z]+\|moodle\.basis-europe\|mod/(page\|book)/view` |
| Copy Vale config as is | webforJ's glob `*.{md,txt}` skips `.mdx` | Use `*.{md,mdx,txt}` and prove it with a deliberate violation. Add BBj terms to the Google acronym and heading exceptions |
| `scripts: ['/js/...']` | Docusaurus does not prefix `baseUrl` on `scripts` or stylesheets | Use a baseUrl constant (`/Courses/js/...`). Watch SCSS `url(/...)`, raw `<img>` and `<a href="/files/...">` too |
| `overview`, `samples` and `resources` are unnumbered | Unnumbered files sort after numbered ones, so the overview ends up last | Number them |
| Book-level `_category_.json` carries the icon | With `dirName: '<book>'` the book folder's own category file is never rendered | Put book icons on the navbar and landing cards (`src/data/books.js`). Spike this. Give every chapter `_category_.json` an explicit `link` |
| Course 2 has `<pre>`, YouTube as `<a>`, six assignments | No `<pre>` (code is `<code>` containing `<p>`/`<br>`); YouTube is `<video><source src="https://youtu.be/ID">`; there are **five** assignments | Detect code blocks on `<code>`, and keep a `<pre>` branch for course 4 (86 `<pre>` blocks there) |
| Resolve images by timestamped filename | All 9 course-2 images are named `image.png` or `image (1).png` | Resolve by the context tuple. Name images `<chapter-slug>-NN.png`. Write alt text by hand |
| Flag 2022 screenshots from filenames | DWC-Course already renamed its images to CamelCase | sha1 the DWC images and match them against course-4 `contenthash` values; flag when the Moodle filename has a 2022 date |
| Flatten resource ZIPs | Two different `Sample.bbj` files exist | Unzip each resource into its own subfolder |
| Components after converted content | The throwing build would fail | Build components first |
| Gap audit after go-live | PROJECT.md decision says before go-live | Do it before go-live and before the redirect map is cut |
| `upload-pages-artifact@v3`, `deploy-pages@v4` | Current majors are v5 for both, and `checkout`/`setup-node` are at v7 | Use the current majors |
| Copy webforJ dependencies | `_sidebar-icons.scss` needs `@tabler/icons` | Rewrite `package.json` deliberately |

### Architecture (ARCHITECTURE.md)
The three artefacts meet only at the Markdown tree and one URL contract, and data flows one way.

The site uses one docs plugin instance serving `docs/docs/<book>/`. Adding a book takes four things: a folder, a sidebar line, a navbar item and a landing card.

Components:
1. **Site config:** `docusaurus.config.js`, `sidebars.js` and the `src/data/books.js` registry.
2. **Theme and components:**
   - `src/theme/*`: the copied overrides, plus new `Admonition/Types.js` and `prism-include-languages.js`.
   - `src/components/*`: YouTube, ExpandableCode, TableWrapper.
3. **Converter:** `tools/moodle2docusaurus.py`, 8 stages: unpack, parse, plan, DOM, markdownify, post-process, write, report. Stages 1-4 stay importable for the gap audit.
4. **DWC relocation:** a script driven by `import/dwc-image-map.tsv`, with columns old name, new path, sha1, pages and 2022 flag.
5. **Redirect generator:** reads the old sitemap and an exceptions table, then writes per-route stubs (meta refresh, canonical link, fallback link, `location.hash` forwarding) plus a `404.html`, verified against the new sitemap.

### Critical Pitfalls (PITFALLS.md)

**1. MDX strictness**
- Problem input: `{ }`, `<>`, markdownify autolinks, void tags.
- Prevention: compile every generated file with `@mdx-js/mdx` inside the converter.

**2. Moodle reference forms the seed misses**
- Problem input: `$@...@$` tokens, absolute pluginfile URLs, duplicate hashes, `$@NULL@$` section names.
- Prevention: resolve by the context tuple and extend the counters and the grep.

**3. Redirect build**
- Problems:
  - Fragments are dropped and there is no 404 page.
  - The mapping is not a prefix swap: `/` goes to `docs/dwc/overview`, `/search` goes to `/`, plus a double-segment route in chapter 1.
- Prevention:
  - Snapshot the old `build/` and `sitemap.xml` before the relocation.
  - Order: deploy, curl-verify, update the README, then archive.

**4. Gates that fail silently**
- Problems: hooks left at `warn`, Vale skipping `.mdx`, absolute paths that ignore baseUrl.
- Prevention:
  - Prove every gate with a deliberate failure.
  - Prove that a deployed deep URL loads all its assets.

**5. Sidebar and slug behaviour**
- Problems:
  - Unnumbered files sort last.
  - `index.md` sits next to a child with the same name.
  - `generated-index` slugs collide.
  - `03a-` prefixes are not stripped.
- Prevention: number every file, give every `_category_.json` an explicit link, and assert unique slugs.

**6. Hygiene**
- Gitignore `import/unpacked/` and the course-4 `.mbz` on day one. Store the archive as a release asset and record its SHA-256.
- Check the course-2 archive for personal data before committing it.
- Add `THIRD_PARTY_NOTICES.md` and per-file MIT headers.
- Self-host the fonts (GDPR).
- Pin or vendor `dwc-ui.css`.

## Implications for Roadmap

Ten suggested phases:
1. **Scaffold and proven deploy:**
   - Rewrite `package.json`, copy the SCSS set and theme overrides, use the baseUrl constant, set the gates to throw.
   - Two stub books, `books.js`, the landing page, dark and light mode.
   - `.gitignore`, notices, fonts, pinned CSS.
   - Spikes: category icon, chapter index detection, swizzles on 3.10.2.
2. **Repo hygiene and CI:** Vale with the right glob and exceptions, the deploy, test-build and reviewdog workflows, `CONTRIBUTING.md`, `CLAUDE.md`, first Pages deploy.
3. **Shared components:**
   - Admonition `Types.js` and `.alert--exercise`, YouTube, ExpandableCode, TableWrapper, the MDXComponents registration.
   - The Prism BBj extension, a fixture page, search config, the brand-asset request.
   - Spike: swizzle order and search on `npm run serve`.
4. **DWC relocation (pure):** snapshot the old build first, then the image map, scripted `git mv`, Markdown images, the samples sync script, numbered top-level files.
5. **Converter and intro-bbj:**
   - Per-file MDX compile gate, a code-classification review CSV.
   - Self-test totals: 28 chapters, 5 exercises, 1 overview, 9 images, 10 videos, 4 resources, 1 skipped module, 0 unresolved references.
   - Commit the converter and the generated pages separately.
6. **Exercises:** `9N-exercise-*.mdx` pages in both books, with DWC inline exercises extracted and missing ones taken from Moodle assignments.
7. **DWC gap audit (before go-live):**
   - One commit series, one commit per chapter, with no slug renames.
   - Reuse converter stages 1-4 in an `--audit` mode with a `<pre>` branch.
   - The 2022 content-hash join lands here if Phase 4 didn't do it.
8. **Hand review, Vale, syntax check:** review in both themes, Vale clean, every `.bbj` checked, screenshot TODO flags, `docs/ROADMAP.md`.
9. **Acceptance and go-live:** the gates proven, the grep empty, the sidebar order diffed, the PR build green, `llms.txt` checked, a deep-URL check on live Pages.
10. **Redirect build and archive:** generator, mapping table, `404.html`, hash-preserving stubs, curl verification, README update, then archive.

Phases that need research or a spike: 1, 3, 5, 7 and 10. Phases 2, 4, 6, 8 and 9 follow standard patterns.
