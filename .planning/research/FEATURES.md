# Feature Landscape

**Domain:** Public, reading-only, multi-book developer training site (Docusaurus, webforJ docs look)
**Researched:** 2026-10-03
**Confidence:** MEDIUM. Scope and tooling come from the project spec (`.planning/migration-seed.md`, `PROJECT.md`, HIGH for intent). Claims about docs.webforj.com and comparable course-as-docs sites (Docusaurus docs, Stripe/MDN-style docs, Rust Book/mdBook, freeCodeCamp-style readers) come from prior knowledge and were not re-verified live in this pass (MEDIUM/LOW). Docusaurus-native capabilities are well known (MEDIUM-HIGH). Verify plugin versions against Docusaurus 3.9 during phase planning.

Hard boundary: NO LMS features (login, enrolment, submissions, grading, progress/completion tracking). Anything touching state per reader is out.

## Table Stakes

Missing any of these makes a docs/course reader feel broken or unfinished.

| Feature | Why Expected | Complexity | Notes / Dependencies |
|---------|--------------|------------|----------------------|
| Per-book sidebar navigation (autogenerated, numbered folders) | Readers need chapter structure and position | Low | Docusaurus `autogenerated` sidebar, `_category_.json`. Needs naming convention (`01-` prefixes, kebab-case). One sidebar per book in `sidebars.js` |
| Top navbar with one item per book (dropdown past ~3 books) | Switch books without going home | Low | Depends on sidebars per book. Navbar dark style from webforJ SCSS |
| Landing page with book cards | Multi-book site needs an entry point | Low-Med | `src/pages/index.js`, reuse `_category.scss` card look. Depends on book `overview.mdx` and logo/cover assets from Stephan. Adding a book = one new card (document in CLAUDE.md) |
| Book overview page per book | Orientation: audience, prerequisites, outline | Low | `overview.mdx`, linked from `_category_.json` `link` |
| Full-text search | Core doc-site expectation (Cmd/Ctrl+K) | Low | `@easyops-cn/docusaurus-search-local`. Multi-book: index all docs, consider per-book hint in results. Algolia block commented in place. Caveat: local search needs a production build to work, not `start` |
| Syntax highlighting with a custom BBj grammar | Whole product is code; unhighlighted BBj looks amateur | Med | `src/prism/bbj.js` + `prism-include-languages.js` + `additionalLanguages`. Keywords verified via BBj MCP. Prerequisite for the "every fence has a language" rule and the Moodle language classifier |
| Copy button on code blocks | Universal expectation | Low | Docusaurus built-in; confirm it survives the `CodeBlock/Line` override and `ExpandableCode` wrapper |
| Line highlighting / titles on code blocks | Teaching material points at lines | Low | Built-in Prism magic comments and `title=`. Use sparingly |
| Collapsible long code blocks (>40 lines) | Keeps pages scannable | Low-Med | `ExpandableCode` from webforJ. Depends on MDXComponents registration |
| Image zoom on click | Screenshots are small and text-heavy (up to 15 per page) | Low | `docusaurus-plugin-zooming`. Check works in both themes and with colocated images |
| Colocated images with required alt text | Accessibility and maintainability | Low-Med | `./img/` per section, kebab-case. `onBrokenMarkdownImages: 'throw'` enforces existence; alt text needs a review pass or lint rule (Vale does not check alt) |
| YouTube embeds (privacy-enhanced, lazy) | Intro book relies on videos | Low | `YouTube` component, `youtube-nocookie`, required `title`, globally registered. Depends on MDXComponents. No cookie banner needed if embed stays nocookie (legal note, not legal advice) |
| Downloadable samples | Readers run the code locally | Low-Med | `static/files/<book>/` plus `examples/<book>/` kept in sync; "Download" paragraph per chapter. Drift between the two copies is the risk (see PITFALLS) |
| Exercises as `:::exercise` admonitions | Both books have hands-on tasks | Low-Med | Custom admonition keyword in config + `_alerts.scss`. Exercise pages `90-`+. Optional `<details>` solution. Depends on admonition registration before content migration |
| Standard admonitions (note/tip/info/warning/danger) | Callouts are baseline | Low | Built-in; keep in keyword list when adding `exercise` (the list replaces defaults) |
| Tabs | Variants (BUI vs DWC, OS) | Low | `Tabs`/`TabItem` registered in MDXComponents |
| Dark and light mode, no flash, DWC tokens in both | Developers expect dark mode; webforJ look is the brief | Med | `dwc-theme-switcher.js` mirrors `data-theme` to `data-app-theme`. Needs both themes checked per page (spec hand-review step). Mermaid and prism theme must follow |
| Table of contents (right rail) and heading anchors | Navigate long chapters, deep-link | Low | Built-in; `Heading` override from webforJ. Content headings start at H2 |
| Prev/next pagination | Linear book reading is the core use case | Low | Built-in. Order must match Moodle outline / old DWC order. Exercises sorted after chapters via `90-` prefix |
| Breadcrumbs | Orientation in nested books | Low | Built-in |
| Edit on GitHub link | Contribution path, standard in the webforJ look | Low | `editUrl: .../tree/main/docs/` |
| Responsive/mobile layout | Phone/tablet reading is common | Low | Infima + webforJ SCSS; check wide tables (`TableWrapper`) and code overflow |
| Redirects for old DWC-Course URLs | Public links must not 404 (Core Value) | Med-High | Two layers: (1) redirect-only build in old repo, one meta-refresh `index.html` per old route (generate from old sitemap/build), canonical + fallback link; (2) `plugin-client-redirects` inside Courses for future renames (start empty). Depends on final DWC slugs after numeric-prefix stripping and the flat-vs-grouped sidebar decision. Needs a test that every old route maps to a live new page |
| Broken link/anchor/image gate in build | Quality gate named in spec | Low | `onBrokenLinks/Anchors` and Markdown hooks set to `throw`; `test-build.yml` PR gate |
| SEO basics: per-page title and description, canonical, sitemap, robots | Discoverability | Low | Front matter `title`/`description` (<=160 chars); Docusaurus classic preset generates `sitemap.xml`. Note `baseUrl: /Courses/` must be respected in sitemap |
| Social cards (OG/Twitter image) and favicon, logo | Link previews when shared | Low | Needs assets from Stephan (BASIS-level logo + cover). Per-page override optional |
| `llms.txt` / `llms-full.txt` | Matches webforJ, AI-readers of docs | Low | `docusaurus-plugin-llms`. Verify output respects `baseUrl` and covers both books. LOW-MEDIUM value for readers, near-zero cost |
| Footer with copyright | Spec | Low | Single HTML block |
| Accessibility baseline | Public site, developer audience, legal exposure in EU | Med | Keyboard-navigable search/theme toggle, contrast in both themes (DWC tokens), alt text, iframe `title`, skip link (Docusaurus built-in), no color-only meaning in exercise admonition (use label "Try it yourself") |
| Mermaid diagrams | Already on DWC site, keeps architecture diagrams as text | Low | `@docusaurus/theme-mermaid`; verify dark mode rendering |
| Prose lint (Vale) and CI deploy to GitHub Pages | Maintenance table stakes for this project | Med | Not user-facing but gates content. Moved DWC pages will have many findings |

## Differentiators

Not expected on a reading site, but add real value. Pick cheap ones; none may require per-reader state.

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| Estimated reading time and "last updated" per page | Sets expectations for chapter-length reading | Low | `showLastUpdateTime` needs git history; weak after relocation (all dates = migration commit) unless history preserved. Reading time needs a swizzle or plugin. Defer |
| Per-chapter learning objectives / prerequisites block | Turns docs into course | Low | Content convention, not code. A tiny `:::info Prerequisites` pattern. Good value, put in CLAUDE.md |
| "Possible solution" `<details>` under exercises | Self-check without grading | Low | Native HTML, already in spec |
| Exercise index per book (DocCardList or generated list) | Find all hands-on tasks fast | Low | `DocCardList` already registered; link from overview. Depends on `90-` exercise naming |
| Cross-book "next steps" links (Intro BBj -> DWC) | Guides learners through the curriculum | Low | Content links; strengthens multi-book value. Depends on both books being live |
| Per-book search scoping (filter by book) | Reduces noise as books multiply | Med | Local search plugin supports docs route filtering/contexts; Algolia supports facets. Revisit at 3+ books |
| Outdated-screenshot flagging (`<!-- TODO -->`) | Maintenance hygiene | Low | Spec item; grep-able |
| Syntax-checked samples in CI (`bbj_check_syntax`) | Code on the site is guaranteed to run; rare among course sites | Med-High | MCP is an authoring-time tool; a CI-runnable check may not exist. Treat as local/pre-commit gate first. Needs verification of whether BBj syntax check can run headless |
| Downloadable sample ZIP per chapter generated at build | Removes sync drift between `examples/` and `static/files/` | Med | Build script copying/zipping from `examples/`. Replaces manual dual-copy; worth considering |
| `llms-full.txt` per book | Lets users feed one book to an assistant | Low-Med | Plugin may need config per book |
| Algolia DocSearch (+ Ask AI) | Best-in-class search | Low (config) + wait time | Needs public site and approval; config commented in place |
| Print-friendly stylesheet / PDF per book | Training material is often printed | Med | `@media print` SCSS is cheap; real PDF export is a separate pipeline. Print CSS only is a good value/cost ratio |
| Giscus comments (GitHub Discussions) | Reader questions | Low (tech), Med (moderation) | Component exists in webforJ; deliberately not enabled first release. Requires GitHub account to comment, which is not an LMS login |
| Announcement bar | Site news | Low | Mechanism kept; disabled by default |
| Version/applicability badges ("BBj 24.02+") | Clarifies version scope of content | Low-Med | Content convention or tiny badge component. Do not copy webforJ `DocChip` |
| Feedback "Was this helpful?" widget | Signal for authors | Med | Needs analytics backend, which is out of scope; skip unless linked to a GitHub issue template (Low) |

## Anti-Features

| Anti-Feature | Why Avoid | What to Do Instead |
|--------------|-----------|-------------------|
| Login, accounts, enrolment | Out of scope; reading-only | Public pages, no auth |
| Progress tracking, "mark as done", completion badges, certificates | LMS; also needs persistence (even localStorage invites scope creep) | Plain prev/next navigation and bookmarkable URLs |
| Graded or interactive quizzes, submission upload | LMS | Exercises as text with optional `<details>` solution |
| Due dates or cohort/schedule UI | Moodle leftover | Drop during conversion |
| Sync back to Moodle / two-way tooling | Markdown is the source of truth | Throwaway converter |
| Live code runner / embedded BBj playground | No server side on GitHub Pages; BBj needs runtime | Downloadable samples + screenshots/GIFs |
| webforJ-specific components (ComponentDemo, DocChip, JavadocLink, gallery, MUI, TableBuilder, AskMenu) | Wrong domain, drags in MUI/Java demo server | Only Tabs, DocCardList, ExpandableCode, TableWrapper, YouTube |
| webforJ i18n translator pipeline / locale dropdown | Single English audience | `locales: ['en']` |
| Re-hosted video files | Cost, storage, copyright | `youtube-nocookie` embed |
| Analytics/cookie banner (gtag/GTM) | No IDs, adds consent burden | Omit; reconsider with a privacy-friendly option later |
| Blog, versioned docs, version dropdown | No release cadence per book | Remove blog; single version per book |
| Reader comments on day one | Moderation burden | Giscus later if wanted |
| Raw `<iframe>` or inline-styled HTML in content | Bypasses tokens, breaks dark mode, not lintable | `<YouTube />`, Markdown, DWC tokens |
| Moodle-era artefacts (pluginfile links, Moodle URLs, `<br>` runs, inline span styles) | Break build gates | Grep acceptance test, converter cleanup |
| Hardcoded colors | Break dark/light parity | `--dwc-*` tokens via SCSS |
| Wholesale conversion of Moodle course 4 | Duplicates the better DWC-Course rewrite | Gap audit only |
| Custom domain work now | No domain planned | Stay on `basishub.github.io/Courses` |

## Feature Dependencies

```
Naming convention (kebab-case, NN- prefix, 90+ exercises)
  -> autogenerated sidebars -> prev/next order, breadcrumbs, exercise ordering
  -> redirect map for old DWC URLs (needs final slugs)

webforJ SCSS/tokens + dwc-ui.css + theme switcher
  -> dark/light parity -> exercise admonition style, Mermaid, prism theme, YouTube styling, book cards

BBj Prism grammar
  -> language-tagged fences -> copy button/ExpandableCode behave
  -> Moodle <pre> classifier (needs grammar names to match)

MDXComponents registration (Tabs, DocCardList, ExpandableCode, TableWrapper, YouTube)
  -> YouTube placeholders from converter
  -> long-code collapse in converter output

Admonition keyword config ('exercise' + defaults)
  -> exercise pages (DWC extraction, Moodle assignments)

Colocated images + onBrokenMarkdownImages throw
  -> converter image mapping, DWC relocation (IdealImage removal)
  -> zooming plugin

Logo + social cover (from Stephan)
  -> navbar, landing page, SEO social cards

Final DWC slugs (flat vs grouped sidebar decision)
  -> client-redirects config AND old-repo redirect build

Book overview pages + _category_.json
  -> landing book cards, navbar items, category icons

Search (local) -> needs production build to test; Algolia later replaces via commented config
DWC gap audit (before go-live) -> additions to pages, must come after pure relocation commit
Gap audit and redirect build -> redirect build only after Courses is live
```

## MVP Recommendation

Prioritize (all table stakes, in dependency order):
1. Theme scaffold with working dark/light, navbar, footer, config gates (throw on broken links/images).
2. Naming convention, autogenerated per-book sidebars, overview pages, book-card landing page.
3. Code experience: BBj Prism grammar, copy buttons, ExpandableCode, image zoom, Mermaid.
4. Content components: YouTube, `:::exercise`, Tabs/DocCardList, TableWrapper.
5. Search (local), SEO/social cards, sitemap, `llms.txt`, edit-on-GitHub, accessibility pass.
6. Old-URL redirect map plus redirect-only DWC-Course build (requires live Courses and final slugs).

Include one or two cheap differentiators: exercise index via `DocCardList`, "Possible solution" details, prerequisites/objectives convention, print stylesheet.

Defer:
- Algolia DocSearch: needs public site and approval.
- Giscus comments: moderation cost.
- Generated sample ZIPs from `examples/`: nice, but manual dual-copy works at two books; revisit when drift appears.
- CI-run BBj syntax check: confirm feasibility first, begin as a local gate.
- Per-book search scoping, last-updated dates: low value at two books / poor git history after move.
