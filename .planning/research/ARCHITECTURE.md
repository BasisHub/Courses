# Architecture Patterns

**Domain:** Multi-book Docusaurus reading site (webforJ look) + throwaway Moodle converter + repo relocation + redirect-only legacy build
**Researched:** 2026-10-03
**Overall confidence:** HIGH for site/sidebar structure and the .mbz facts (inspected the real archive); MEDIUM for converter heuristics (derived from one course); MEDIUM for two Docusaurus edge behaviours flagged below.

## Recommended Architecture

Three independent build artefacts that meet only at the Markdown tree and one URL contract:

```
                       (one-time, throwaway)
 import/*.mbz ──► tools/moodle2docusaurus.py ──► docs/docs/intro-bbj/**  (committed Markdown = source of truth)
                                                  docs/static/files/intro-bbj/**, docs/examples/intro-bbj/**

 BasisHub/DWC-Course (git clone) ──► scripted/manual relocation ──► docs/docs/dwc/**, docs/examples/dwc/**,
                                                                    docs/static/files/dwc/**
                                                  │
 import/*course-4*.mbz ──► gap audit (manual+script-assisted) ──► import/dwc-gap-audit.md ──► edits in docs/docs/dwc/**

 docs/  (Docusaurus 3.9, one docs plugin instance, N sidebars)
   docusaurus.config.js ── sidebars.js ── src/{css,theme,components,prism,pages} ── static/js
        │  npm run build (throws on broken links/anchors/images)
        ▼
   docs/build ──► GitHub Pages  https://basishub.github.io/Courses/   (deploy.yml)
        │
        └─ build/sitemap.xml ──► target-exists check for the redirect map

 DWC-Course old sitemap (26 routes) ──► tools/gen-redirects (small script, lives in the DWC-Course repo or Courses/tools)
        ──► redirect-site/ (index.html per old route + 404.html) ──► DWC-Course main (Pages)
```

|-----------|---------------|----------|

| `docs/src/css/custom.scss` + partials | DWC token mapping, webforJ look, `.alert--exercise`, `cat-icon--*` rules | Infima (via sass plugin), dwc-ui.css (CDN, runtime) |
| `docs/src/theme/*` | Swizzled overrides: `Heading`, `CodeBlock/Line`, `MDXContent`, `MDXComponents.js`, `prism-dwc-theme.js`, **new** `Admonition/Types.js` (registers `exercise`), `prism-include-languages.js` (registers bbj) | `@theme-original/*`, `src/components`, `src/prism` |

| `docs/src/pages/index.js` | Book-card landing at `/`; reads a small book registry (`src/data/books.js`: slug, title, description, icon, first-doc path) | books.js, `_category_.json` is NOT the source (see Pattern 2) |
| `docs/docs/<book>/` | Content only: MDX/MD, colocated `img/`, `_category_.json` per section | sidebars.js (via dirName) |

| `.github/workflows/{deploy,test-build,reviewdog}.yml` | Pages deploy (working-dir `docs/`), PR build gate, Vale | `docs/` |
| Redirect generator + `redirect-site/` | One `index.html` per old route, generated from old sitemap; lives in DWC-Course repo `main` | old sitemap in, new Courses sitemap for verification |

### Data Flow

Direction is strictly one-way: Moodle/DWC-Course -> Markdown -> HTML. Nothing flows back. After the converter is accepted, its output is hand-edited and `tools/` is never re-run on `docs/` (re-running would clobber edits; add a `--out` guard that refuses to write into a non-empty book folder without `--force`).

## Decision (2): one docs plugin instance, per-book autogenerated sidebars

**Recommendation: single `@docusaurus/plugin-content-docs` instance (the classic preset's), `routeBasePath: 'docs'`, `path: 'docs'` (default), one sidebar per book.** Confidence HIGH.

Why it fits the URL contract: docs live at `docs/docs/<book>/...`; doc IDs and URLs are path-derived, so `docs/docs/dwc/01-gui-to-bui-to-dwc/index.md` becomes `/Courses/docs/dwc/gui-to-bui-to-dwc` (numeric prefixes stripped, `trailingSlash: false`). The book folder name is the URL segment for free. No route config per book.

```js
// sidebars.js
export default {
  introBbjSidebar: [{type: 'autogenerated', dirName: 'intro-bbj'}],
  dwcSidebar:      [{type: 'autogenerated', dirName: 'dwc'}],
};
// navbar items
{type: 'docSidebar', sidebarId: 'dwcSidebar', label: 'BBj DWC Training', position: 'left'}
```

(`docSidebar` navbar items link to the first doc of that sidebar and highlight while any doc of the sidebar is active; verified in Docusaurus 3.9.2 docs via Context7.)

Why not multiple instances: each needs `id`, `path`, `routeBasePath` (`docs/dwc` would nest under the default instance's `docs` route and fight it), its own `sidebarPath`, its own `editUrl`, its own navbar `docsPluginId`, and its own search/llms/redirect handling. webforJ's second instance (`cookbook`) exists because that is a different product area; two sibling books gain nothing from that. Multiple instances only pay off for per-book versioning, which is out of scope. Adding book N is then: a folder, one sidebar line, one navbar item, one landing card, one icon rule (matches the CLAUDE.md "Adding a new book" recipe).

Consequences to design for (these differ from the seed's mental model):

1. **Book-level `_category_.json` is not rendered when a sidebar uses `dirName: '<book>'`.** The autogenerated sidebar lists the book folder's *children*; the book folder's own `_category_.json` (label, `cat-icon` className, link) is only used when the book appears as a category inside a `dirName: '.'` sidebar. Under per-book sidebars the book icon/label/description belong to the navbar item and the landing card (`src/data/books.js`). Keep a book-level `_category_.json` only if you want it as metadata, but do not rely on its `className`. (Confidence MEDIUM-HIGH: inferred from the autogenerated-sidebar semantics in the docs, not tested; verify in the scaffold phase with a 5-minute spike.) If the seed's "sidebar icon per book" is truly wanted, the alternative is one sidebar `[{type:'autogenerated', dirName:'.'}]` as webforJ does, which shows all books in every sidebar and loses per-book navbar highlighting. Recommend per-book sidebars and icons on navbar/cards.
2. **`overview.mdx`, `samples.mdx`, `resources.mdx` have no numeric prefix, so autogenerated ordering puts unprefixed items after prefixed ones.** `overview` must come first and `samples`/`resources` last: set `sidebar_position` in front matter (`overview`: `-1` or `0` and renumber, `samples`: 98, `resources`: 99) or prefix the filenames (`00-overview`, `98-samples`, `99-resources`; prefix is stripped from URLs, so the redirect map is unaffected). Note `00-prerequisites` and `overview` both want position 0; choose `overview` = `sidebar_position: 0`, `00-prerequisites` -> `01-prerequisites`? Simpler: keep `00-prerequisites`, give overview `sidebar_position: -1`. `docSidebar` navbar links go to the first item, so this also decides where a navbar click lands.
3. **Category index detection vs the old chapter 1 layout.** Default `isCategoryIndex` treats `index`, `readme`, or a file whose name equals the folder name as the category's landing doc. `01-gui-to-bui-to-dwc/` contains both `index.md` and `03-gui-to-bui-to-dwc.md` (the old site had exactly these routes: `/gui-to-bui-to-dwc` and `/gui-to-bui-to-dwc/gui-to-bui-to-dwc`). Whether the numeric prefix is stripped before the name match is not stated in the docs I could reach (LOW-MEDIUM). Mitigation, do it for every chapter folder regardless: set explicit `"link": {"type": "doc", "id": "dwc/<chapter-slug>/index"}` in each `_category_.json` (explicit metadata wins), and verify both old URLs build. Otherwise one of the two docs can silently become a non-sidebar-visible category index or the wrong one.
4. **`generated-index` slugs are global.** Default slug is `/category/<label-slug>`; two books with a section called "Getting Started" would collide. Always set `"link": {"type":"generated-index","slug":"/<book>/<section-slug>", ...}` in section `_category_.json` (the converter emits this). Moodle section summaries are all empty in course 2, so `description` has nothing to carry; omit it rather than invent text.
5. Doc IDs are `<book>/<path>` so `overview` in both books does not clash. `onBrokenLinks: 'throw'` and the three markdown hooks are in config; `plugin-client-redirects` only acts in production build, keep its `redirects: []` list empty.

### `routeBasePath: 'docs'` and the landing page

`/` is `src/pages/index.js` (not a docs route), `/docs` itself has no page unless a doc claims it. Either leave `/docs` as a 404 (nobody links to it) or add a `plugin-client-redirects` entry `/docs -> /` - cheap and avoids a dead URL; recommend adding it.

## Decision (1): scaffold adopting webforJ pieces

Copy as units, in this order, because each later unit depends on the earlier:

1. `package.json` deps trimmed (drop `@mui/*`, `@emotion/*`, carousel, openai, cookbook tooling). Keep `sass`, `docusaurus-plugin-sass`, `prism-react-renderer`, `clsx`.
2. `src/css/custom.scss` + partials, minus `_blog`, `dwc-doc-components`, `.MuiChip-root` rules. These `@use` each other (`_root`/`mixins` first); copy the whole set at once or the compile fails. License notice header kept (MIT).
3. `static/js/dwc-theme-switcher.js`, `link-decorator.js` registered in `scripts`; `dwc-ui.css` + fonts in `headTags` (runtime CDN dependency, note for offline builds: not needed at build time).
4. `src/theme/`: `prism-dwc-theme.js`, `Heading`, `CodeBlock/Line` (+`CodeBlock` wrapper as in webforJ), `MDXContent`, trimmed `MDXComponents.js`. webforJ's theme folder also holds `BlogLayout`, `BlogTagsListPage`, `NavbarItem`: skip the blog ones; inspect `NavbarItem` before copying (it is likely tied to the version badge/locale items; omit unless needed).
5. New (not in webforJ): `Admonition/Types.js` adding `exercise` (config `docs.admonitions: {keywords: ['exercise'], extendDefaults: true}` alone is not enough; the type must also map to a component, per the Docusaurus admonition docs), `prism-include-languages.js`, `src/prism/bbj.js`, `YouTube`.
6. `src/pages/index.js` landing, `static/img/` brand assets (placeholder logo until Stephan supplies the BASIS one; the phase that needs it asks).

Note the seed's `.planning` mention of `additionalLanguages` with `'bbj'`: DWC-Course lists `'bbj'` without a grammar; the old build tolerated it (Prism-react-renderer ignores unknown languages / falls back). Do not carry that line over without the grammar being registered; once the grammar exists, a fence tagged `bbj` highlights, before that it silently renders plain.

### Stages (each a pure function over a typed model; stages 3-5 are where the work is)

```
1 unpack      detect tar.gz vs zip (file magic, not extension) -> import/unpacked/<name>/   (gitignored)
2 parse       moodle_backup.xml (modules: id, type, section, title, dir) + course.xml
              sections/section_N/section.xml (name|None, sequence, visible)
              activities/*/{book,assign,resource,page}.xml + module.xml(visible) + inforef.xml
              files.xml -> index by (contextid, component, filearea, itemid, filename); skip filename=='.'
              -> model: Course{ sections[ Section{ modules[ Book{chapters sorted by pagenum} | Assign | Resource | Page | Label ] } ] }
              (HTML fields are XML-escaped text: ElementTree .text already unescapes once; do NOT html.unescape twice)
3 plan        pure mapping model -> list of Output{path, title, html, kind}; slugs (kebab, ASCII, de-umlaut),
              position prefixes, 9N exercise numbering per section, id map moduleid/chapterid -> output path,
              file copy plan (img naming <chapter-slug>-NN, resources to static/files + examples with ZIP unpack in subfolder)
              Mapping decisions applied once here: section label keeps its leading number or not (seed: decide once).
4 DOM pre-process (BeautifulSoup + html.parser; NOT lxml: the input nests <p> inside <code>, which libxml2 restructures)
   a. resolve @@PLUGINFILE@@ -> ./img/<name> (images) or /files/<book>/<name> (others); count unresolved
   b. <video><source youtu.be> | <a youtu.be|watch?v=> | bare URL -> <youtube id=...> placeholder; de-dup per block
   c. code detection: a <code> is a BLOCK when it contains <br>/<p>, or is the sole non-whitespace child of a <p>/body,
      or is multi-line; otherwise inline. Block -> synthesize <pre><code>: convert <br> and <p> boundaries to \n, strip
      spans, unescape. Inline <code> stays inline (watch `{`, `}`, `<` inside inline code in MDX, handled in stage 6).
   d. language classify for block code (seed 6.1 rule list; BBj is default for this course; css/html/js heuristics)
   e. collapse <br> runs, unwrap style-only <span>, drop empty headings/paragraphs, rank-compress headings to start at H2
   f. <img> alt: empty -> placeholder + report entry; unwrap <a><img></a> if same target
   g. internal moodle links: assert none (fail loudly), external untouched
5 markdownify  markdownify (or pandoc gfm) with heading_style=ATX, code via the synthesized <pre>; custom handler turns
               <youtube> into a sentinel token that survives conversion
6 post-process escape `{ } <letter` outside fences; heading spacing; sentinel -> <YouTube id title />; long fences (>40) wrapped in
               <ExpandableCode>; front matter (title, description first sentence <=160, quoted); exercise wrapper
               :::exercise Try it yourself ... ::: ; Download paragraphs; trailing newline; forbidden-string grep
7 write        refuse non-empty target without --force; deterministic (stable ordering, mapping file img-map.json
               for stable re-runs); _category_.json per section incl. generated-index slug
8 report       counts + lists: pages, images (+ placeholder-alt list), videos, resources, unresolved PLUGINFILE (must be 0),
               unclassified code blocks, unresolved internal links (must be 0), skipped modules with reason, forbidden-string hits
```

Component boundary note: stages 2-3 know Moodle; stages 4-6 know only HTML/Markdown and a path map; stage 7 knows the Docusaurus layout. Keep them in one file (throwaway) but as separate functions so the first run's problems (nearly all in stage 4c/4d) are fixable in isolation. Unit-test nothing; the report counts above plus `npm run build` are the test.

Things that will bite on the first run (all derived from the real data): (a) code blocks arriving as `<code><p>…<br>…</p></code>` with inline `<span style>` pieces and `&nbsp;`-style indentation (the BBj program in book 16 ch. 3 uses leading spaces inside spans: preserve them); (b) double-listed video URLs; (c) every image named `image.png`; (d) chapter order by `pagenum`; (e) empty heading spacers; (f) `h4`/`h5` jumping levels; (g) dangling `<br>` after block elements.

## Decision (4): DWC-Course relocation + image renaming map

Pure relocation = mechanical, scriptable, reviewable as one commit. Boundary: it changes paths and image syntax only, never prose.

```
DWC-Course/docs/<chapter>/…           -> docs/docs/dwc/<NN-chapter>/…        (folder names already numbered 01..12)
DWC-Course/docs/{index,prerequisites,samples,resources}.md -> dwc/{overview,00-prerequisites,samples,resources}.mdx
DWC-Course/static/img/<CamelCase>.png -> docs/docs/dwc/<chapter>/img/<kebab>.png    (chapter = the page that references it)
DWC-Course/samples/<NN_Name>/         -> docs/examples/dwc/<NN_Name>/  and docs/static/files/dwc/<NN_Name>/  (+ LICENSE, README)
```

Order of operations:
1. Build the **rename map first** as data (`import/dwc-image-map.tsv`: old name, new path, referencing page(s)), generated by scanning the old pages for `require('@site/static/img/...')` / `<Image img=...>` usages. It records, not assumes: images referenced from two pages (copy to the first chapter and reference by relative path from the second, or duplicate; prefer one copy plus relative `../01-x/img/` link) and unreferenced images (flag, move to the nearest chapter or drop with a note).
2. Apply with a script reading the map, rewriting `<Image img={require(...)} alt=... />` to `![alt](./img/name.png)`. Rewriting must keep `alt`, and `title`/size props have no Markdown equivalent (list them; Docusaurus image zoom plugin replaces click-to-enlarge). Note `import Image from '@theme/IdealImage'` lines go away; pages that had no other JSX can stay `.md`; seed requires the four top-level pages to become `.mdx`.
3. Flag 2022-timestamp originals (`screenshot 2022-…`) with `<!-- TODO: screenshot outdated? -->` while renaming, since the timestamp is lost after kebab-casing (store in the map).
4. Put the mapping table in the commit message (as seed says) *and* keep the TSV in `import/` (the commit message is not greppable later; also the gap audit needs old->new names).
5. Samples: `examples/dwc/` is the CI syntax-check target; `static/files/dwc/` is the download copy. Generate one from the other in a script rather than hand-syncing (CLAUDE.md says "keep in sync"; make `tools/sync-samples.sh` the enforcement, or a CI diff check).
6. Per chapter `_category_.json` with explicit `link` to the chapter doc (see Decision 2, point 3); no icons on sections; no group folders (flat, decided).
7. Anything the build then flags (broken link, `/img/...` absolute paths in prose, links like `/DWC-Course/...` caught by the acceptance grep) is fixed in this same commit; these are path fixes, not content edits. Old internal links use root-relative paths because `routeBasePath: '/'`; each must become a relative file link (`./02-x.md`) so they survive `baseUrl`.

Old route -> new route contract (consumed by the redirect build): `/DWC-Course/<p>` -> `/Courses/docs/dwc/<p>` for all 26 sitemap routes, with only two exceptions: `/` -> `/docs/dwc/overview`, and `/search` -> `/` (search page is not content). Because folder numbers are stripped, slugs stay identical. Verify with the new build's sitemap, not by assumption. If the gap audit or exercise extraction renames anything, put it in the redirect exceptions table, not in the content.

## Decision (5): gap audit flow

Runs after the relocation, before go-live, as its own commit series; reads Moodle course 4 (never converted wholesale).

```
course-4.mbz ──(reuse converter stages 1-4 only, --audit mode, no write to docs/)──► import/unpacked/dwc-audit/<page-id>.md
   (Markdown dumps of every Page/Book chapter, with images listed by name, stored outside docs/ and gitignored)
        │
        ▼  per Moodle page 1A, 1B, … -> candidate dwc page (mapping table kept in import/dwc-gap-audit.md header)
 unit of comparison: paragraph | code sample | screenshot
        │  automated first pass: normalised-text shingle overlap and code-block fingerprints to pre-mark "already covered"
        ▼
 import/dwc-gap-audit.md   one section per Moodle page; each item: source ref, excerpt, verdict keep|drop|covered, target page
        ▼
 kept items -> edits in docs/docs/dwc/** (+ new images with the same renaming rules), one commit per chapter
        ▼
 exit check: no item without verdict; build + Vale pass; assignments from course 4 with no DWC exercise become 9N-exercise pages
```

Boundaries: the audit reuses the converter's unpack/parse/DOM stages (so course 4's `<pre>` blocks, 2022 screenshots with timestamped names, and per-page `files.xml` resolution are handled by already-proven code) but writes outside `docs/`. This is the one reason to structure the converter stages as importable functions. Course 4 is much more image-heavy (16.7 MB, up to 15 screenshots/page, real `<pre>` blocks) so the stage 4c heuristics will need a `<pre>` branch even though course 2 has none.

Exercises: the DWC inline-exercise extraction (3.4 step 4) and course-4 assignments (12) feed the same `90-exercise-*.mdx` pattern; do the extraction in the relocation->audit gap, after the exercise admonition exists.

## Decision (6): redirect-site generation

Pure function: `old sitemap (or old build/ output) + exceptions table -> redirect-site/`. 

- Input: `https://basishub.github.io/DWC-Course/sitemap.xml` (fetched 2026-10-03: 26 URLs plus the root; includes `/search`). Prefer the sitemap taken from the old repo's final `build/` rather than the live one, to freeze it before the old site is replaced.
- For each route `p`: write `redirect-site/<p>/index.html` (serves both `/p` and `/p/` on Pages) with `<meta http-equiv="refresh" content="0; url=NEW">`, `<link rel="canonical" href="NEW">`, a visible fallback `<a href="NEW">`, and a 3-line script forwarding `location.hash` (meta refresh drops fragments; deep links like `#some-heading` otherwise land at the top). Root gets `index.html` in the repo root. Add `404.html` redirecting unknown old paths to `/Courses/docs/dwc/overview` (covers `/DWC-Course/foo` typos and the routes the sitemap missed). Add `<meta name="robots" content="noindex">`? No: redirect pages should stay indexable-neutral; `canonical` is the signal. Skip `noindex`.

## Patterns to Follow

### Pattern 1: path-derived structure, no hand-written navigation
Folder tree + `_category_.json` is the only structure source; sidebars.js has one autogenerated line per book. Converter and relocation both only need to write correct folders. Why: new books never touch component code.

### Pattern 2: book registry for landing + navbar
`src/data/books.js` (`{slug, title, description, icon, sidebarId, start}`) feeds `index.js` cards and is referenced when adding navbar items; `_category_.json` handles sections only. Avoids relying on book-level `_category_.json` semantics (Decision 2.1).

### Pattern 3: one-way converter with a quantified report
The report's numbers are the contract (counts listed above); the pass criterion is zeros plus a green build, not eyeballing.

### Pattern 4: explicit link metadata in `_category_.json`
`link` is always explicit (`doc` id or `generated-index` with a book-scoped slug) so index detection and slug collisions never depend on defaults.

## Anti-Patterns to Avoid

### Anti-Pattern 1: multiple docs plugin instances for books
Brings per-instance sidebars, route-prefix collisions with `routeBasePath: 'docs'`, plugin ids in every navbar item. Use one instance.

### Anti-Pattern 2: resolving Moodle files by filename within the module
All nine course-2 images are called `image.png`/`image (1).png`. Key on `(contextid, itemid, filename)`.

### Anti-Pattern 3: assuming `<pre>` and anchor-style YouTube links
Real data has neither. Write the DOM stage against the real HTML (dump 2-3 chapters first), not the seed's description.

### Anti-Pattern 4: re-running the converter on hand-edited output
After acceptance the Markdown is the truth. Guard writes, and move the converter out of any CI/npm script.

### Anti-Pattern 5: flattening resource ZIPs
Two different `Sample.bbj` exist. Unzip into per-resource subfolders.

### Anti-Pattern 6: content edits inside the relocation commit
Defeats the reviewability that motivated the separate gap-audit series.
